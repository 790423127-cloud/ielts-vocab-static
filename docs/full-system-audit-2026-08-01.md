## 已修复

### P1 性能：全站导航后台加载无关大型数据

首页在空闲 700 ms 后会自动预取所有学习路由，并额外下载 basic、538、phrases、meaning-6000 等数据。真实浏览器可观察到无操作时仍出现大量请求和 7 条未使用 CSS 预载警告。这会与 37.5 MB 主词库的解析争抢网络和主线程。

修复：删除无条件全站预热；保留鼠标悬停、按下或键盘聚焦时的按需路由和对应数据预取。相关性能回归用例通过。

### P1 交互：工具栏左右键误触发翻词

Next 与静态版都允许在 input/select 获得焦点时继续把左右键交给全局翻词监听，因此调整下拉框或位置滑块会跳词。

修复：输入框、范围滑块、下拉框和可编辑元素保留自己的左右键行为；页面空白处左右键仍翻词。Next 版同时忽略按键自动重复，避免一次长按连续越过多个词。

### P2 数据检测：正常变形被误判为截断词

旧检测器把 `activate → activated`、`archive → archives` 等明确标注为过去式/复数的正常关系当成“词头被截断”，产生 126 条误报。

修复：当 longer form 明确标注为 plural、past tense/participle、present participle/gerund 或 third-person 时，不再视为截断词。真实词库误报从 126 降为 0，同时 `bil → bill`、`belov → beloved` 的损坏样例仍可识别。

### P2 移动端导航状态

位于“更多”菜单内的页面没有让“更多”显示当前页状态。

修复：统一计算移动端更多菜单的活动项，并补充 `aria-current="page"`。

### P2 依赖安全

开发依赖中的 `brace-expansion 1.1.16` 命中高危拒绝服务公告。已仅更新锁文件到 1.1.18。生产依赖和全依赖审计现在均为 0 个已知漏洞。

## 尚未修改的正式数据问题

### P1 主词库质量门禁（3 条）

1. `suggests t`：疑似阅读导入截断，缺词性、难度、释义和例句，同时被识别为多词词条。
2. `excluding`：缺词性、难度、释义和例句。
3. `immune system`：内容完整，但作为固定复合词保存在单词层，尚未显式标记 `lexicalizedCompound`，因此质量门禁将其计为“词组混入单词库”。

这些记录需要人工确认“修正、保留并标记、还是删除”，不应由审计过程自动决定。

### P1 meaning-6000 悬空引用（2 条）

- `word_excel_3f79bb7b435b`：`e`。
- `word_excel_1b16b1df538b`：`n`。

两条仍在 meaning-6000 中，但主词库对应 ID 已不存在，导致 3 个释义训练完整性断言失败。按用户说明，可能是主词库词条曾被删除；应选择“从 meaning-6000 同步删除”或“恢复主词库记录”，不能只改测试数字。

### P2 morphologyAudit 元数据漂移

- 实际 stored-form 链接 1,710，嵌入审计元数据仍为 1,708。
- 当前后缀候选加登记退役项为 3,903，元数据仍为 3,894。
- 两个物理变形目标在主词库中不存在：`astronaut → astronauts`、`marshalled → marshalling`。

需要先确认这两个变形应作为独立物理记录、仅作 accepted form，还是移除链接，再统一重建 morphologyAudit；不能只把统计数字改成当前值。

### P3 音频缓存卫生

- `.audio-cache` 共 31,003 个文件，约 1.31 GB，其中 10 个为 0 字节。
- 音频读取链已检查文件大小，0 字节文件不会作为有效音频返回，因此当前不会直接造成无声播放。
- 可在用户确认后运行现有孤儿/无效缓存清理，不建议审计时直接删除缓存。
