# G类完整词库补丁：范围、证据与人工复核边界

## 本次实施内容

本分支实施一个可重复运行、幂等的G类词库补丁，而不是直接手工覆盖约32MB的主词库文件。

构建前脚本会：

1. 从唯一正式单词源 `.static-export-cache/words.json` 读取主词库；
2. 对 `public/data/words.json` 写出完全相同的同步结果；
3. 添加G类阅读主动词、扩展识别词和专业参考词；
4. 添加填空答案表达、复合表达和真题上下文表达；
5. 修复已确认的错误释义、残缺例句和题库中出现的熟词生义；
6. 清除字面上的“无中文释义”占位标记；
7. 无法安全确定语义的专名、非标准词形或来源残留只降为参考并进入待复核队列，不猜测具体词义；
8. 生成 `public/data/gt-complete-learning-plan.json`，按稳定ID组织四阶段计划；
9. 保留原有ID以及 `status`、`favorite` 和复习进度字段；
10. 更新主词库基线元数据，并输出详细报告。

- 补充 `stock`、`carrier`、`host`、`conductor`、`litter`、`gum`、`bill`、`fuel` 等题库语境义；

这些改动采用保守策略：只写入能够从G类题库语境或现有词条冲突中高置信确认的内容。

## 关于“审核全部13,809词”

本补丁会对全库执行结构性检查，包括：

- 缺失释义或定义；
- 泛化/缺失词性；
- 过短或疑似残缺例句；
- “无中文释义”占位标记；
- 仍需结合来源判断的专名或非标准词形；
- 重复词头和重复稳定ID。

但结构检查不等于逐条完成13,809个词的权威词典级人工语义核验。对于没有题库证据、词义高度依赖上下文或来源不明的词条，本补丁会列入 `semanticReviewCandidates`，而不是伪造释义后宣称全部审核完成。

因此，本次交付定义为：

> 全库结构审计 + 高置信人工语义修复 + 题库熟词生义补充 + 不确定项隔离与持续复核队列。

## 发布与回滚

- `npm run build` 的 `prebuild` 会自动应用词库和学习入口补丁；
- 可先运行 `npm run vocab:gt-complete:dry-run` 查看预览；
- 补丁数据集中保存在 `data/gt-complete/`；
- 删除prebuild调用并恢复生成文件即可回滚；
- 本分支不修改用户浏览器中的个人进度语义。
